# 01 需求与范围

> 版本：v0.1（设计基线，待确认） · 日期：2026-11-17

## 1. 背景与目标

`dsh-docker` 已经证明「一个镜像 + 一个 Caddy 入口」可以稳定跑 DeepSeek Harness。现在要把它从**单用户自部署**变成**多用户云电脑**：

1. 用户不再自己碰 Docker / 域名 / 证书，登录控制台就能用；
2. 管理员能集中管理版本、配额、用户与整机资源；
3. 所有用量可计量、可追溯，为后续扩容（多机 / K8s / GPU）留出接口。

**成功标准（一期）**：一个不懂 Docker 的同事拿到邀请码后，5 分钟内拥有自己的 `https://<name>.dsh.example.com`，并能从控制台一键进入；管理员能看清每个实例的 CPU/内存/磁盘/时长消耗，并能导入、启用、禁用 DSH 版本。

## 2. 角色

| 角色 | 说明 | 关键权限 |
|---|---|---|
| 用户 `user` | 平台使用者，每人 1 个实例 | 管理自己的实例、快照、镜像、文件、Key；看自己的用量 |
| 管理员 `admin` | 平台运维者 | 用户/邀请/套餐/配额、镜像版本、全部实例、全站与整机监控、审计、公告、工单、系统设置 |
| 系统 `system` | 后台任务身份 | 生命周期、计量、对账、GC，不受配额限制 |

一期只有两级角色，不引入 RBAC 细粒度权限；`admin` 拥有全部管理权限。二期如需「只读运维」「客服」再拆。

**约束**：一个用户只有一个实例（UNIQUE），实例的对外地址由用户名决定且不可变。

## 3. 用户侧需求

### US-01 注册与登录

- 管理员创建账号，或生成**邀请码**；用户凭邀请码设置用户名/密码完成注册。
- 用户名即子域名：`^[a-z][a-z0-9-]{2,30}$`，保留字拒绝（`console`、`api`、`admin`、`www`、`status`、`mail`、`caddy`、`wildcard`…）。
- 登录失败限流；密码 argon2id；支持改密；管理员可强制重置（下次登录必须改密）。
- 验收：错误密码 5 次/分钟后返回 429；邀请码一次性、可设过期时间。

### US-02 我的实例

- 首次进入显示「创建我的云电脑」，可选**套餐**与**DSH 版本**（仅管理员启用的版本）。
- 生命周期操作：启动、停止、重启、休眠、删除；操作中显示进度（SSE 推送状态）。
- 实例卡片展示：状态、版本、套餐、CPU/内存/磁盘规格、剩余时长、最近活跃时间。
- 删除需二次确认（输入用户名），删除后数据保留 N 天（默认 7 天）再由 GC 清理。
- 验收：停止后容器不存在但数据保留；再次启动 15 秒内进入 `running`（不含首次拉镜像）。

### US-03 一键进入（无感登录）

- 点击「打开」后，控制台确保实例运行，读取本次启动的 DSH token，浏览器最终落在 `https://<user>.dsh.example.com/` 且**已登录**。
- 用户全程看不到 token；最终地址栏是干净 URL。token 只在一次 302 的 `Location` 中出现（浏览器历史会留下该条记录，见 02 §9 / R-04）。
- 实例休眠时点击「打开」= 唤醒 + 等待 + 进入，页面显示唤醒进度。
- 验收：冷启动到可见 GUI ≤ 60 秒；token 获取失败时给出可操作提示（「重启实例」按钮），不白屏。

### US-04 用量看板

- 展示：今日/本月活跃时长、剩余时长、CPU 核时、内存 GB·时、磁盘占用、网络出入。
- 折线图支持 24h / 7d / 30d；数据延迟 ≤ 2 分钟。
- 配额 80% 时站内提醒，100% 时实例自动停止并提示「联系管理员扩容」。
- 验收：活跃时长与实际使用误差 ≤ 5%（以 30 秒采样为基准）。

### US-05 快照

- 手动创建快照（备注 ≤ 200 字）；创建过程中实例短暂不可用（停止或 pause），页面明确提示。
- 快照列表：大小、创建时间、DSH 版本、备注；可恢复、删除、下载（可选）。
- 受套餐 `max_snapshots` 限制；超出时提示删除旧快照。
- 验收：恢复后 `settings.yaml`、会话、workspace 文件与快照时一致；恢复失败可回滚到恢复前状态。

### US-06 环境镜像

- 「保存为镜像」= 对实例当前**系统层**做 `docker commit`，生成个人镜像；之后可用它创建/重建实例。
- 明确告知：**用户数据（`/data/dsh`、`/workspaces`）不在镜像里**，要连数据一起保存请用快照。
- 个人镜像列表：名称、大小、基础版本、创建时间；可删除；受 `max_user_images` 限制。
- 验收：commit 产物不含明文 `DEEPSEEK_API_KEY` / `LITELLM_API_KEY`（构建时清空环境变量），且能成功启动新实例。

### US-07 版本切换

- 用户可在管理员启用的版本中切换；切换 = 用新镜像重建容器、复用原数据目录。
- 切换前自动创建快照（可配置），并提示「跨大版本可能不兼容」。
- 验收：切换失败自动回滚到旧版本并恢复运行。

### US-08 文件管理

- 在控制台内浏览/上传/下载/删除/重命名/新建目录，根目录为实例 workspace。
- 单文件上限默认 1 GB（分片上传），禁止路径穿越与符号链接逃逸。
- 验收：`../../etc/passwd` 类路径返回 400；下载支持 Range。

### US-09 模型 Key

- 默认使用管理员配置的平台 Key；用户可填自己的 DeepSeek Key 覆盖，保存后**重启实例生效**。
- 界面只显示掩码（`sk-****abcd`），任何 API 不返回明文。
- 验收：数据库落盘为 AES-GCM 密文；日志与审计中不出现明文。

### US-10 公告与工单

- 首页展示未过期公告；用户可提交工单（文字 + 最多 3 张截图），查看回复。
- 验收：新回复站内红点；工单状态 `open / processing / resolved / closed`。

### US-11 自动休眠与唤醒

- 默认 30 分钟无活动自动休眠（停止容器、保留数据），不扣时长。
- 休眠期间访问子域名看到唤醒页；点击后自动拉起并跳转。
- 用户可在设置中调整自己的休眠阈值（可选范围 15–240 分钟，管理员可关）。

## 4. 管理员侧需求

### AS-01 用户与邀请

- 列表/搜索/筛选（状态、套餐、到期）；创建、禁用、启用、重置密码、删除。
- 邀请码：批量生成、设置角色与过期时间、查看使用情况、吊销。
- 用户详情：实例状态、配额、近 30 天用量、操作审计、强制停机。

### AS-02 套餐与配额

- 套餐 CRUD：CPU 核数、内存 MB、磁盘 GB、每月时长（分钟）、快照数、镜像数、GPU 数（二期）。
- 单用户可覆盖任意字段；套餐变更即时影响规格（重启后生效）。
- 手动赠送/扣减时长，必须填原因，写入 `quota_ledger`。
- 周期重置：自然月（`Asia/Shanghai`）自动重置 `seconds_used`。

### AS-03 镜像版本管理

- 导入方式：
  1. 从 Registry 拉取 `repo:tag`（支持私有仓库凭据）；
  2. 上传 `docker save` 的 tar（分片 + 校验）。
- 每个版本记录：版本号、镜像引用、digest、大小、架构、来源、变更说明、导入人。
- 启用/禁用/设为默认；禁用后不可新建或切换，运行中的实例不受影响（可批量通知）。
- 导入后自动校验：能读出 `dsh.version` 标签、`dsh --version` 可执行；可选冒烟启动（`--dump-config`）。
- 验收：导入失败有明确原因；同一 digest 不重复入库。

### AS-04 实例总览

- 全站实例表格：用户、状态、版本、规格、CPU/内存实时、运行时长、最近活跃。
- 强制操作：启动/停止/重启/删除、改套餐、迁移版本、打开 Web 终端、查看日志（最近 500 行）。
- 批量操作（停止全部、按版本筛选后重启）。

### AS-05 用量大屏

- 总览卡：在线用户数、运行实例数、今日活跃时长、本月总核时、配额告警数。
- 排行：Top N 用户（时长/CPU/内存/磁盘）。
- 趋势：近 30 天活跃时长、实例数、CPU 核时。
- 支持按用户下钻。

### AS-06 物理机监控

- CPU 使用率/负载、内存、磁盘各挂载点、网络吞吐、容器数、Docker 版本与磁盘占用。
- 时间范围 1h / 24h / 7d；阈值告警（磁盘 > 85%、内存 > 90%、负载 > 核数×2）。
- 一期单机；数据来自 `node-exporter`，30 秒采样，保留 7 天原始 + 1 年小时聚合。

### AS-07 审计

- 记录所有写操作：谁、何时、IP、动作、目标、变更前后（脱敏）。
- 可按人/动作/时间检索；不可修改、不可删除（仅归档）。
- 保留 180 天。

### AS-08 管理员 Web 终端

- 对任意实例打开 `docker exec` 交互终端（xterm.js + WebSocket），支持窗口缩放。
- 每次会话记录审计（开始/结束/操作者），会话中禁止粘贴密钥的提示。
- 仅 `admin` 可用；可全局开关。

### AS-09 公告与工单处理

- 公告：Markdown、级别（info/warning/maintenance）、定时发布、置顶、过期。
- 工单：队列、指派、回复、关闭；回复触发站内通知。

### AS-10 系统设置与运维

- 设置项：基础域名、控制台名称、默认套餐、默认版本、休眠阈值、是否允许用户自选版本、快照保留天数、上传上限、维护模式。
- 一键对账：DB ↔ Docker ↔ Caddy 三方状态修正。
- 一键 GC：清理悬空容器/镜像、过期快照、已删除用户数据（需二次确认）。
- 系统健康：MySQL / Redis / Docker / Caddy / 磁盘余量。

### AS-11 备份

- MySQL 每日逻辑备份；快照目录独立；提供恢复脚本与演练步骤（见 05 文档）。

## 5. 非功能需求

| 维度 | 指标 |
|---|---|
| 容量 | 不绑定机型：按探测到的 CPU/内存/磁盘动态准入；支持 ≥ 200 用户，同时运行实例数由内存余量决定（示例：64C/256G 约 50 个标准实例） |
| 时延 | 普通 API P95 < 300 ms；启停 API 返回 < 500 ms（异步执行）；状态推送 < 2 s |
| 可用性 | 控制面重启不影响运行中的实例；Caddy 重启后 60 s 内自动重建全部路由 |
| 数据 | 计量数据不丢（Redis 计数 5 分钟落库一次，宕机最多丢 5 分钟）；审计 append-only |
| 安全 | 实例无特权、cap_drop ALL、no-new-privileges、pids/内存/CPU 限制；密钥加密；全站 HTTPS |
| 可观测 | JSON 结构化日志 + `request_id`；`/metrics` Prometheus；关键动作审计 |
| 可维护 | 全部配置走环境变量 + `settings` 表；数据库变更走 Alembic；镜像可回滚 |

## 6. 范围边界

**一期做**：上面 US/AS 全部（GPU 除外）。
**一期不做**：

- 多物理机调度、K8s（架构预留 Driver，不做实现）；
- Token 级计费（只按时长 + 资源；DeepSeek 账单为准）；
- 在线支付/充值；
- 用户自定义域名；
- 实例内多用户协作/共享链接；
- 邮件/短信通知（先站内信，接口预留）；
- 高可用（MySQL/Redis 单点，接受维护窗口）。

**二期（已登记，不许忘）**：GPU 支持、多节点/K8s、token 计量网关、MFA、S3 快照、共享镜像模板。详见 06 文档。

## 7. 已确认决策

### 第一轮（2026-11-17）

| # | 问题 | 结论 | 理由 |
|---|---|---|---|
| 1 | 后端栈 | Python + FastAPI | 与 dsh-docker 同栈；docker SDK / 异步 / 资源采集最顺 |
| 2 | 部署形态 | 先单机，预留多节点 | 多节点后期直接上 K8s，不自己造调度器 |
| 3 | 访问方式 | 每用户子域名 | DSH cookie 绑 authority，子域名天然隔离；路径前缀会破坏静态资源与 WS |
| 4 | 进入方式 | 控制台账号 + 自动注入 token | 用户无感；后端有读容器日志权限 |
| 5 | 时长口径 | 双记录，按活跃会话扣 | 防止忘关容器把时长耗光；同时保留运行时长供运维分析 |
| 6 | 快照/镜像 | 两者都做 | 数据归档 + 系统层 commit，语义不同 |
| 7 | 配额模型 | 套餐 + 单用户覆盖 | 管理批量、个体可调 |
| 8 | 闲置策略 | 自动休眠 + 点击唤醒 | 省内存、少扣时长，数据不丢 |
| 9 | 前端 | Element Plus | 后台组件全、团队熟悉 |
| 10 | 一期附加 | 文件管理、公告工单、自选版本、管理员终端 | 运维与体验必需 |
| 11 | 域名布局 | `console.` + `{user}.` | 同属一个泛域名，隔离清晰 |
| 12 | 实例数量 | 每人 1 个 | 配额与内存核算最简单 |
| 13 | 模型 Key | 平台默认 + 用户可覆盖 | 开箱即用且能分清成本 |
| 14 | Token 计量 | 一期不做 | 需出口网关，二期再说 |
| 15 | GPU | **二期**，一期只预留字段与驱动接口 | 硬件与调度复杂度高 |
| 16 | TLS | 泛域名 + Caddy internal CA | 内网无需公网 DNS；客户端装一次根证书 |

### 第二轮（2026-11-17）

| # | 问题 | 结论 | 理由 |
|---|---|---|---|
| 17 | 物理机规格 | **弹性**：运行时探测容量 + 动态准入，不针对某机型适配 | 开源项目要能跑在任何规格的机器上 |
| 18 | 基础域名 | 保持占位，全部可配置；TLS 支持 `internal_ca` / `acme` | 开源使用者填自己的域名 |
| 19 | 镜像来源 | **只导入**；不构建、不派生；`login-gate` 由 `dsh-docker` 侧移除 | 控制台保持薄，镜像构建归 CI |
| 20 | 注册后 | 进入创建向导，不自动建实例 | 省资源，用户确认规格后再分配 |
| 21 | 平台 Key 风险 | 一期接受（仅可信用户 + 消费上限 + 审计）；网关列 1.5 期第一项 | 见 06 R-01 |

## 8. 术语

| 术语 | 含义 |
|---|---|
| 实例 / instance | 一个用户专属的 DSH 容器 + 数据目录 + 子域名 |
| 套餐 / plan | 一组资源与时长规格 |
| 快照 / snapshot | `/data/dsh` + workspace 的归档文件 |
| 用户镜像 / user image | 对实例系统层 `docker commit` 的产物 |
| 活跃时长 | 有 HTTP 请求或明显网络活动的秒数 |
| 唤醒页 | 休眠实例的子域名上由控制面返回的过渡页 |
| 对账 / reconcile | 用 DB 为准修正 Docker 与 Caddy 的漂移 |
